# TASK-0422: Blog detail page crashes on every post ("xəta baş verdi")

## Problem
Clicking any blog post throws immediately → global-error ("Xəta baş verdi / Texniki
komanda məlumatlandırıldı"). The blog LIST page works; only the DETAIL page crashes,
and it does so for ALL posts, right away (confirmed: error appears the instant you
open a post, before scroll/paywall).

## Root cause
The blog detail page (`app/[locale]/blog/[slug]/page.tsx`) calls, at the very top of
render, two DB queries that had NO error handling:
1. `getSlugRedirect(slug)` — queries `slug_redirects` (added in migration
   `drizzle/0016_slug_redirects_and_cascade.sql`).
2. the `guru_boxes` select inside `getBlogPostDetail` (migration `0015`).

Unlike the ads repository — which explicitly wraps its public-page query in try/catch
("Must NEVER throw — a missing/empty ads table must not break a public page") — these
blog queries were unguarded. If either table is missing on prod (migration not applied),
the query throws and the **entire blog detail page crashes for every post**, while the
list page (which calls neither) keeps working. This exactly matches the symptom.

## Fix (defensive — correct regardless of DB state)
- `lib/db/blog-repository.ts` `getSlugRedirect()` — wrap the query in try/catch,
  return `null` ("no redirect") on failure.
- `lib/db/blog-repository.ts` `getBlogPostDetail()` — wrap the `guru_boxes` select in
  try/catch, fall back to `[]` (render the article without guru boxes).

A public blog page must never crash because an optional table is missing — this brings
blog queries in line with the ads repository's existing "never throw" pattern.

## Operator action (to fully restore, not just stop the crash)
Confirm + apply on prod (Neon):
```sql
SELECT * FROM slug_redirects LIMIT 1;   -- if "relation does not exist" → this was it
SELECT * FROM guru_boxes LIMIT 1;
```
If missing, run the pending migrations (`0015`, `0016`, and any between the last
applied and 0016) so redirects + guru boxes work again. The code fix stops the crash;
the migration restores the features.
