# TASK-0563 — News run no longer red when one article fails

Owner: Doğan. Approved 2026-11-26 («yap paşam»).

## Problem
About half of the `news-ingest` runs were red and sent "News pipeline FAILED" mail, although news reached Telegram
every day (`news_approval_delivery` state `sent`: 11–25 per day, 18.11–25.11). Run #407 (25.11): 11 synthesized and
delivered, 2 articles failed (`[forbidden] qadağan söz: Agentlik`, `[parse] invalid JSON`) → `process.exit(1)`.

## Change
- `lib/news/synthesize.ts`: `SynthesizeResult.warnings` — per-article draft failures (AI error, forbidden word,
  bad JSON, thrown drafting error). `errors` keeps system failures only (DB, API key, Telegram delivery).
- `scripts/newsdata-synthesize.ts`: warnings are printed and shown as `::warning` annotations. Exit 1 only on
  `errors`, or when every attempted article failed (`synthesized === 0` with warnings).

## Not in this change: late/missing scheduled runs
GitHub runs this repo's cron jobs hours late and drops most of them (news-ingest 05:00 UTC slot started 13–15 UTC;
news-collect ran 2–3×/day instead of 12). Since 23.11 only one owner delivery per day (~19:00 Baku). Needs an
external trigger — owner decision.

## Validation (local, 2026-11-26)
- `eslint` on both files: clean.
- `tsc --noEmit`: 23 errors before and after, none in the changed files (pre-existing on main).

## Rollback
Revert the PR: any single article failure turns the run red again.
