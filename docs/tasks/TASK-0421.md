# TASK-0421: Registered members invisible in admin panel — SST fix

## Problem
Self-registered users were invisible in the admin members panel. Root cause: the
admin list (`/api/admin/members` GET) reads only from `member_profiles`, but
`/api/auth/register` inserted only into `users` — never a `member_profiles` row.
A `member_profiles` row was created only when (a) an admin manually adds a member,
or (b) the user later opens and saves their profile. Users who registered and never
edited their profile therefore existed in `users` but not `member_profiles`.

Confirmed on live data: 7 registered users, only 1 in the panel, **6 invisible**
(all email-verified, real businesses: Piramida, Belgianchocolate, Turan Qastro, +3 test).

## Changes
- `app/api/auth/register/route.ts` — after creating the user, also insert a
  `member_profiles` row (email, fullName, phone, company, role='member',
  emailVerified=false, source='registration') with `onConflictDoNothing()`.
  Wrapped in try/catch so a profile-insert failure never blocks account creation.
- `app/api/auth/confirm/route.ts` — on email verification, also set
  `member_profiles.email_verified = true` for that email, so the panel's verified
  badge stays accurate (users ⇄ member_profiles kept in sync).

## Backfill (one-time, run in Neon SQL — not code, no deploy)
```sql
INSERT INTO member_profiles (email, full_name, company, phone, role, email_verified, source, created_at)
SELECT u.email, u.name, u.company, u.phone, COALESCE(u.role, 'member'),
       u.email_verified, 'registration-backfill', u.created_at
FROM users u
WHERE u.deleted_at IS NULL
ON CONFLICT (email) DO NOTHING;
```
Makes the 6 existing invisible members appear immediately.

## Not touched
`lib/db/schema.ts` (member_profiles table already exists — no migration), auth
contract (userId/role only), PROTECTED files. No new route, no new table.
