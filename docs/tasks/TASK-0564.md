# TASK-0564 — Workflow guards (Actions minute budget)

Owner: Doğan. Source: global rule «GitHub Actions dakika bütçesi» §5 (every workflow: concurrency +
cancel-in-progress, timeout ≤15). Open item from the 2026-11-26 analysis.

## Problem
- `state-snapshot.yml`: timeout 20 (>15), no concurrency. It ran `npm ci` + full `npm run build`
  every week only to write `BuildStatus: PASS` into `docs/STATE.md`; `scripts/generate-state.mjs`
  imports only `node:fs` / `node:path`. Every push to main is already built by `ci.yml`.
- `drift-audit.yml`, `fetch-news.yml`, `auto-merge-content.yml`: no concurrency.
- `.claude/CLAUDE.md` said «Vercel deployment»; production is Hostinger.

## Change
- state-snapshot: drop `npm ci` + build, `BUILD_STATUS="main CI (ci.yml)"`, timeout 5, concurrency.
- concurrency + `cancel-in-progress: true` on drift-audit, fetch-news, auto-merge-content
  (auto-merge grouped per PR number).
- `news-ingest.yml` keeps `cancel-in-progress: false` on purpose (DB writes must not be cut mid-run).
- `.claude/CLAUDE.md`: Hostinger.

## Validation (local, 2026-11-26)
- All 8 workflow files parse (ruby YAML).
- `node scripts/generate-state.mjs` without `node_modules` deps: exit 0.

## Estimated saving
~8–10 min/week → ~1 min/week (≈30–40 min/month).

Revert the PR.
